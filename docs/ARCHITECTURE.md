# Architecture

## Layout

```text
lib/
  main.dart, bootstrap.dart      config → Firebase → ProviderScope
  firebase_options.dart          generated by `flutterfire configure`
  app/                           app widget, router, routes, global providers
  core/                          config, errors, money, theme, utils, widgets, l10n
  data/firebase/                 paths, helpers, tracked streams, bootstrap
  features/<feature>/
    domain/                      immutable models + pure logic (unit-tested)
    data/                        repositories + Riverpod providers
    presentation/                screens and widgets
```

Features: auth, home, tours, membership, expenses, settlements, itinerary,
map, location_sharing, notes, packing_list, activity_feed, notifications,
settings.

## State management

Riverpod 3 only. Repositories are plain classes exposed via `Provider`.
Firestore listeners are `StreamProvider.autoDispose.family` keyed by tour ID,
so a listener exists only while a screen watches it and is cancelled on
dispose. Derived state (`balancesProvider`, `permissionsProvider`,
`activeMembersProvider`) is computed from those streams and recomputes only
when its inputs change. `ProviderScope(retry: null)` stops failing streams
(e.g. permission-denied after removal) from retrying in a loop.

The tour workspace builds only the selected tab, so leaving the Map tab
cancels the locations listener. `trackListener()` counts live listeners for
the diagnostics page.

## Money

`core/money`: integer minor units everywhere; `parseAmount` works on digit
strings; `formatMoney` divides only for display (values are bounded so this
is exact). Splits (`split.dart`) are deterministic: participants sorted by
UID, equal-split remainders go to the first UIDs, weighted splits use the
largest-remainder method. Custom splits must sum exactly.

### Balance sign convention

```
net = paid_for_expenses − share_of_expenses
      + confirmed_settlements_paid − confirmed_settlements_received
```

Positive = should receive; negative = owes. Paying a settlement moves both
parties toward zero. (The brief's formula labels the settlement terms the
other way round; this is the reading that keeps every currency's nets
summing to zero.) Currencies are never merged. Pending (unsynced) expenses
and unconfirmed settlements are excluded. `suggestTransfers` greedily pairs
the largest debtor with the largest creditor (≤ n−1 transfers per
currency); it is a suggestion only.

## Writes, offline and conflicts

Firestore offline persistence provides cached reads and queued writes.

- **Queue-safe writes** (new expense, plan, note, packing, settlement
  submission) go through `commitQueued`: if the server has not acknowledged
  within 6 s the UI says "Saved on this device… will sync", never "saved".
  Unsynced records show "Pending sync" and are excluded from balances.
  IDs are generated before the first attempt so retries cannot duplicate.
- **Server-required operations** use transactions or awaited batches, which
  fail offline: membership approvals/removals, role changes, tour status,
  expense edits/deletes, settlement confirm/dispute/cancel.
- **Conflicts**: expense and note edits compare `revisionCount` inside a
  transaction and refuse to overwrite a newer version (the user is told to
  reopen). Plans are last-write-wins; reorders write one item (sparse sort
  keys) or renumber one day. Packing items are independent documents.
- **Location** writes are dropped (not queued) while offline.
- Screens show a banner when data comes from cache.

## Provider abstractions

- `MapTileSource` (URL template, attribution, User-Agent) from config;
  default OSM tiles via `flutter_map`.
- `PlaceSearchProvider`: `NominatimPlaceSearch` (1 req/s throttle, in-memory
  cache, submit-only) or `DisabledPlaceSearch`; manual entry always exists.
- External navigation uses `geo:` / Apple Maps / OSM URLs via
  `url_launcher` — no SDK keys.

## Location lifecycle

`LocationSharingController` (per tour): permission requested only on start
(foreground "while in use"); balanced accuracy, 50 m distance filter, writes
throttled by `LocationWritePolicy`; stops on expiry, user stop, tour close or
sign-out; pauses GPS and marks the record `paused` when the app is hidden;
resumes on return if the window is still open. The UI hides expired and
paused coordinates by timestamp/status and labels stale ones (> 5 min).

## Notifications

In-app inbox (`users/{uid}/inbox`) for important events; activity feed for
everything else, with an "unseen" badge filtered by the user's expense/plan
preferences. Itinerary reminders are device-local (`flutter_local_notifications`,
inexact scheduling, ≤30 per tour) and resynced whenever the plan changes.
No FCM sender exists in the app.

## Deep links

`app_links` receives `https://<host>/join/<code>` and
`tourboard://join/<code>`; the code is validated with `InviteCodes.parse`.
If the user is signed out, the router stores the code and resumes the join
flow after sign-in.

## Error handling

`classifyError` maps Firebase codes to calm messages; `ErrorState` offers
retry, and permission-denied renders "You're no longer a member". Missing
Firebase config renders a setup screen instead of crashing.
